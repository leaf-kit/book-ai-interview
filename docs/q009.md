# q009, 섞인 답, 해 본 것과 읽은 것이 섞였을 때

**한 줄 요약.** 한 답변 안에서 해 본 부분과 읽은 부분을 갈라 내면 통째로 버리지 않아도 된다.

**판정.** 본인이 경계를 그어 주면 통과입니다. 여기까지는 제가 썼고 여기부터는 받아 썼다고 말하는 것, 그거면 됩니다. 파고들어도 경계가 안 그어지고 계속 우리가 했다로 답하면 안 보냅니다. 숨기려는 게 아니라 경계를 안 세어 본 경우가 많은데, 결과는 같습니다. 디브리프에는 이렇게 적습니다. 경계가 안 그어졌고, 손이 간 함수를 물었더니 영역으로 답했고, 라이브러리와 본인 코드의 경계가 끝까지 불명확했다.

**꼬리 질문.** 직접 구현했냐고 물으면 네 아니오만 돌아옵니다. 그래서 함수 하나를 묻습니다. 함수 이름은 손댄 사람만 기억하거든요. {그 파일에서 손이 제일 많이 간 함수가 뭐였어요?} {그 라이브러리를 열어 보신 적 있어요? 무엇을 보러 들어가셨어요?}


이유와 이야기는 책에 있습니다.
